# 12FZ Chat 统一用户身份方案

## 一、现状问题

当前系统存在三套身份体系混用：

| 场景 | 当前取值 | 问题 |
|------|---------|------|
| 用户登录后 | botId = "admin"（string） | — |
| 邮箱链接 ?token=session-1 打开 | botId = "1"（number） | — |
| friends 表 | user_id 和 friend_id 混着 "admin" 和 "1" | 查好友用 "admin" 找不到 "1" 的记录 |
| friend_messages 表 | from_id/to_id 混着数字和字符串 | 查聊天记录两边对不上 |
| messages.sender_id | 字符串 username / bot_id | 同一个人在不同场景是两个 ID |
| group_members.bot_id | 字符串 | — |
| Agent 与人 | 分开存在 agents 表和 users 表 | Agent 不能加好友，权限体系分裂 |

**根因：没有一个全局唯一的用户标识。**

---

## 二、新架构

```
users 表
  id             SERIAL  PRIMARY KEY  ← 全局唯一标识
  merchant_id    FK → merchants        ← 归属商户
  type           'human' | 'agent'    ← 人 / AI 区分
  username       VARCHAR UNIQUE        ← 登录名 / bot_id
  display_name   VARCHAR               ← 展示名称
  parent_id      FK → users            ← Agent 创建者
  avatar         VARCHAR
  status         VARCHAR               ← 'active'|'inactive'
  created_at     TIMESTAMP
  updated_at     TIMESTAMP

所有身份引用全部改为 FK → users.id：
  friends.user_id / friend_id
  friend_messages.from_id / to_id
  messages.sender_id
  group_members.user_id (原 bot_id)
  groups.created_by
  bot_statuses.user_id (原 bot_id)

新增：
  login_credentials  — 用户登录凭据（密码/手机/微信），挂在 users.id 下
  agent_configs      — Agent 专有配置（model/system_prompt/capabilities），挂在 users.id 下

删除：
  agents 表 — Agent 身份合并到 users
```

## 三、改动清单

### 3.1 新建表

```sql
CREATE TABLE chat.login_credentials (
    id         SERIAL PRIMARY KEY,
    user_id    INTEGER NOT NULL REFERENCES chat.users(id) ON DELETE CASCADE,
    provider   VARCHAR(16) NOT NULL,
    identifier VARCHAR(128),
    credential VARCHAR(256),
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE chat.agent_configs (
    user_id        INTEGER PRIMARY KEY REFERENCES chat.users(id) ON DELETE CASCADE,
    model          VARCHAR(64) DEFAULT 'tk.12fz.com',
    system_prompt  TEXT,
    capabilities   TEXT[] DEFAULT '{}',
    api_key        VARCHAR(256),
    api_url        VARCHAR(256),
    created_at     TIMESTAMPTZ DEFAULT now(),
    updated_at     TIMESTAMPTZ DEFAULT now()
);
```

### 3.2 users 表新增字段

```sql
ALTER TABLE chat.users ADD COLUMN type         VARCHAR(16) DEFAULT 'human';
ALTER TABLE chat.users ADD COLUMN display_name VARCHAR(64);
ALTER TABLE chat.users ADD COLUMN parent_id    INTEGER REFERENCES chat.users(id);
ALTER TABLE chat.users ADD COLUMN avatar       VARCHAR(256);
ALTER TABLE chat.users ADD COLUMN status       VARCHAR(16) DEFAULT 'active';
ALTER TABLE chat.users ADD COLUMN updated_at   TIMESTAMPTZ DEFAULT now();
```

### 3.3 删除表

```sql
DROP TABLE IF EXISTS chat.agents CASCADE;
```

### 3.4 现有表字段类型变更

```sql
-- friends: text → integer FK
ALTER TABLE chat.friends ALTER COLUMN user_id   TYPE INTEGER USING user_id::INTEGER;
ALTER TABLE chat.friends ALTER COLUMN friend_id TYPE INTEGER USING friend_id::INTEGER;
ALTER TABLE chat.friends ADD CONSTRAINT fk_friends_user   FOREIGN KEY (user_id)   REFERENCES chat.users(id);
ALTER TABLE chat.friends ADD CONSTRAINT fk_friends_friend FOREIGN KEY (friend_id) REFERENCES chat.users(id);

-- friend_messages: text → integer FK
ALTER TABLE chat.friend_messages ALTER COLUMN from_id TYPE INTEGER USING from_id::INTEGER;
ALTER TABLE chat.friend_messages ALTER COLUMN to_id   TYPE INTEGER USING to_id::INTEGER;
ALTER TABLE chat.friend_messages ADD CONSTRAINT fk_fmsg_from FOREIGN KEY (from_id) REFERENCES chat.users(id);
ALTER TABLE chat.friend_messages ADD CONSTRAINT fk_fmsg_to   FOREIGN KEY (to_id)   REFERENCES chat.users(id);

-- messages: text → integer FK
ALTER TABLE chat.messages ALTER COLUMN sender_id TYPE INTEGER USING sender_id::INTEGER;
ALTER TABLE chat.messages ADD CONSTRAINT fk_msg_sender FOREIGN KEY (sender_id) REFERENCES chat.users(id);

-- group_members: bot_id → user_id, text → integer FK
ALTER TABLE chat.group_members RENAME COLUMN bot_id TO user_id;
ALTER TABLE chat.group_members ALTER COLUMN user_id TYPE INTEGER USING user_id::INTEGER;
ALTER TABLE chat.group_members ADD CONSTRAINT fk_gm_user FOREIGN KEY (user_id) REFERENCES chat.users(id);

-- groups: text → integer FK
ALTER TABLE chat.groups ALTER COLUMN created_by TYPE INTEGER USING created_by::INTEGER;
ALTER TABLE chat.groups ADD CONSTRAINT fk_group_creator FOREIGN KEY (created_by) REFERENCES chat.users(id);

-- bot_statuses: bot_id → user_id, text → integer FK
ALTER TABLE chat.bot_statuses RENAME COLUMN bot_id TO user_id;
ALTER TABLE chat.bot_statuses ALTER COLUMN user_id TYPE INTEGER USING user_id::INTEGER;
ALTER TABLE chat.bot_statuses ADD CONSTRAINT fk_bs_user FOREIGN KEY (user_id) REFERENCES chat.users(id);
```

### 3.5 后端代码

| 改动 | 说明 |
|------|------|
| auth.go | login() 返回 user_id；session token 对应 user_id |
| http.go 所有 handler | getBotID(r) → getUserID(r) 返回 int64 |
| db/*.go 所有查询 | user 参数从 string 改 int64 |
| model/*.go | 结构体字段改 int64 |
| 新增 GET /api/whoami | 返回 user_id/username/display_name |
| 新增 GET /api/users/:id | 查询用户展示信息 |

### 3.6 前端代码

| 模块 | 当前 | 改为 |
|------|------|------|
| auth.ts | botId = "admin" 或 "1" | userId = 1（number） |
| chat.ts | sender_id: string | sender_id: number |
| 展示名称 | 直接显示 bot_id | 通过 display_name map |
| localStorage key | bot_id | user_id |

## 四、数据迁移步骤

```
1. 停服
2. pg_dump 备份
3. INSERT agents → users (type='agent', display_name=display_name)
4. UPDATE 所有 text ID → integer（username/bot_id → users.id）
5. 执行 ALTER TABLE + ADD CONSTRAINT
6. 创建 login_credentials + agent_configs 并迁移数据
7. DROP agents CASCADE
8. 部署新代码
9. 启动服务
```
